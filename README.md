# Blockwright · MC Building Generator

A working first version of **describe a building → design specification → Minecraft blocks → 3D preview → schematic download**.

The offline planner selects and parameterizes curated medieval, modern, and Japanese-inspired building templates. An optional OpenAI planner can interpret a description into the same bounded design schema. Geometry and block states are always generated by code.

**No model API key?** Connect ChatGPT or Codex through the built-in MCP endpoint. Your assistant plans in chat, calls `create_build`, and returns preview and download links. See [MCP connection instructions](docs/mcp.md).

## Run locally

Requires **Python 3.12+** and **Node.js 22.12+** (tested on Python 3.12 and Node 24).

```bash
cd /workspace/MC-Building-Generator
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci --cache /tmp/mc-building-npm-cache
npm run build
npm start
```

The web preview runs on port **3000**. `npm start` selects the project's Python virtual environment and serves the compiled interface and API together. It works behind preview gateways that forward their own hostnames. You do not need to activate `.venv` or manage two terminals. No database, Minecraft server, or API key is required for offline generation.

For hot reload, `npm run dev` starts the API on port 8000, waits for readiness, and starts Vite on port 3000. Stopping this launcher stops the API it started. Vite restricts forwarded hostnames; for an embedded web preview, prefer `npm start`. If you use hot reload through a gateway, configure its trusted hostname with Vite's `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS` environment variable. Set `PORT` to change the public port and `BLOCKWRIGHT_API_PORT` to change the separate API port in development. `npm test` selects `.venv` automatically. `npm run dev:frontend` is available if you deliberately manage the API separately.

**Open Web preview, rather than the `index.html` source file.** The source HTML is a Vite entry point; a file visualization cannot resolve its modules or run the Python API. Publishing an environment retains files but stops live servers; rerun `npm start` when returning to a restored environment.

## Temporary public test link (no domain or account)

**This route currently cannot run in the selected Codex runtime:** direct DNS fails even after the domain allowlist was saved, and the HTTPS proxy rejects the provider request. No public tunnel URL has been created. For an externally hosted demo with a provider address, see [hosting without a custom domain](docs/hosting.md).

After building the app, run `npm run public`. This downloads a pinned, SHA-256-verified Cloudflare tunnel client and starts a separate offline-only demo. The tunnel prints a random HTTPS address under `trycloudflare.com`. No domain purchase or Cloudflare login is needed.

The link works only while the process and cloud environment keep running; it changes when restarted. The public demo has no AI API key. The normal local server is kept separate. Stop the command to close the link. This is for short-lived testing, not permanent hosting.

The cloud network must allow `*.trycloudflare.com`, `region1.v2.argotunnel.com`, `region2.v2.argotunnel.com`, and `h2.cftunnel.com`. Cloudflare's HTTP/2 tunnel also requires outbound TCP port 7844; an HTTPS-only proxy may not support it. Keep TLS and checksum verification enabled. A saved network draft does not activate network access by itself.

Prepare the verified binary without opening a public link with `.venv/bin/python scripts/public_link.py --prepare-only`.

## Try it

> A 29×25 medieval manor with 2 floors, a corner tower, timber framing and a steep dark roof.

> A modern 33×25 villa with 2 floors. No tower.

> A Japanese 27×23 temple with dark timber beams and white walls.

Use the layer slider and floor-plan camera to inspect interiors. Downloads include `.schem`, `.litematic`, and a JSON design with block coordinates and a material list. The PNG button captures the current view. The seed controls foundation material variation, rather than inventing a new layout.

Building footprints are **15–65 blocks per side**, with **1–3 main floors**. Medieval towers require a width of at least 25 and add two storeys. Terrain and roof overhangs enlarge the exported bounds beyond the footprint. Generated structures include a foundation, windows, paired doors, stair flights, and simple furnishings. They are architectural prototypes, not complete furnished adventures or arbitrary prompt execution.

## Load into Minecraft Java Edition

Both formats target **Java 1.20.1** (`DataVersion 3465`) using blocks available in that version. Newer compatible WorldEdit/Litematica versions should migrate these blocks; older versions and Bedrock are not supported.

- **WorldEdit / FAWE:** put the `.schem` file in your installation's `schematics` directory, use `//schem load building-42`, then `//paste`. The export origin is the minimum X/Y/Z corner of the complete site, not the entrance.
- **Litematica:** put the `.litematic` file in your Minecraft instance's `schematics` directory, load it in Litematica, and create a placement. Its material list can guide survival building.
- Exports include air inside the bounding box. Use a backup or an empty test area when pasting. Block entities and inventories are not generated.

Exports are tested by decoding every coordinate and with the independent Litemapy reader. **Import into an actual Minecraft client has not been tested in this environment.**

## Optional AI planning

### Chat assistant through MCP (no server model API key)

Expand **Build with ChatGPT or Codex** in the sidebar and copy the MCP address into your assistant's custom MCP server settings. The tools use your assistant's existing model access; the server makes no AI API calls. This workflow starts in the assistant conversation, rather than the website's API-planner dropdown. After a tool creates a building, its preview link opens that exact design on the website. See [setup and limits](docs/mcp.md).

### Direct provider API (optional alternative)

Provide `OPENAI_API_KEY` securely in the server's environment and optionally `OPENAI_MODEL` (default `gpt-4.1-mini`), restart the Python server, and choose **AI · API required** in the UI. `.env.example` lists the names; the server does not automatically load `.env` files. Never commit credentials or place them in frontend variables.

The server sends the description to `https://api.openai.com/v1/chat/completions` and validates the returned design before generating any blocks. API charges may apply. Missing credentials or provider failures are reported explicitly; there is no silent fallback. Live provider calls have not been validated without credentials.

## Tests

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
npm run build
```

`litemapy` is a pinned prerelease used only as an independent format reader in tests. Browser tests require a started Python server and Chromium:

```bash
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/browser_smoke.py http://127.0.0.1:3000
# Or use an existing Chromium installation:
CHROMIUM_PATH=/usr/bin/chromium .venv/bin/python tests/browser_smoke.py http://127.0.0.1:3000
```

The browser smoke test exercises WebGL rendering, floor cutaways, camera controls, exports, screenshots, style changes, terrain toggling, invalid input, and the mobile layout. Artifacts are written to the ignored `artifacts/` directory.

## What this first version does not do

Reference-image interpretation, retrieval from example builds, arbitrary floor plans, bridges/ravines, automatic vision critique, iterative refinement, realistic Minecraft textures, and professional-builder quality are future work. The renderer uses simplified block geometry and colors; it is not the Minecraft rendering engine. Validation covers the generated palette, explicit block-state properties, and door pairs, not a full physics, lighting, or navigation simulation.

The server is a local development tool. Generated builds live in memory; restarting clears them, and only the latest eight builds remain downloadable. Download files you want to keep. Multi-user authentication, durable jobs, request quotas, and deployment hardening are not implemented.

See [the architecture and next steps](docs/architecture.md) for the path toward the full pipeline.
